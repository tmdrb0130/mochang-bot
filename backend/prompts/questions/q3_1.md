[문항 의도]
심사 축 — 실현가능성(S) — 심사위원이 확인하려는 것: **정말 만들 수 있는가. 경쟁 대비 무엇이 다른가.**

[프로세스 위치]
④ 해결책 설계 (근거는 ③ 문제 검증).
지금 사람들이 쓰는 대안·경쟁 제품을 먼저 짚고, 거기서 무엇이 부족한지로부터 우리 해결책을 끌어냅니다.

[골자 사용 규칙]
- 펼쳐 씁니다: **기존 대안과 다른 점 · 해결책**.
- 문제는 **한 절로만** 되짚고 다시 설명하지 않습니다 (Q2가 이미 썼습니다).
- 쓰지 않습니다: 수익 방식 · 6개월 계획 · 지원자 역량.
- 수치는 골자의 '인용할 수치' 중 **두 번째 하나만** 씁니다.

[필수 요소]
- 해결하려는 문제를 한 문장으로 정의
- 사용자가 실제로 밟는 사용 흐름
- 왜 기존 방식보다 잘 되는지 — 핵심 동작 원리
- 기존 대안 2종 이상을 실명으로 지목하고 3개 이상 기준으로 비교
- 현재 개발 단계 (아이디어/기획/프로토타입/베타)

[권장 요소]
문단 구성 — 이 순서와 분량으로 2,000자를 채웁니다
1) 한 문장 정의 + 사용자가 얻는 결과 (약 200자)
2) 사용 흐름 (약 400자)
   사용자가 실제로 밟는 단계를 순서대로. 진입부터 결과를 받기까지.
3) 핵심 동작 원리 (약 450자)
   왜 기존 방식보다 잘 되는지. 방식의 이름을 명시합니다.
   검증 가능한 목표 수치를 1개 이상 넣되, 목표임을 밝힙니다. (예: "수십 분 걸리던 작업을 1분 내외로")
4) 기존 대안 2종 이상과의 비교 (약 550자)
   대안을 **실명으로** 지목합니다. "그냥 참는다", "직접 한다" 같은 우회책도 대안입니다.
   **비교 기준을 3개 이상 세워** 같은 기준으로 나란히 놓습니다. (예: 소요시간 / 비용 / 사용자 손이 얼마나 가는지)
5) 그래서 어떤 문제가 실제로 해소되는가 (약 250자)
   Q2에서 제기한 문제와 1:1로 대응시켜 닫습니다.
6) 현재 개발 단계와 남은 일 (약 150자)
   아이디어 / 기획 / 프로토타입 / 베타 중 어디인지 솔직하게. 과장하지 않습니다.

[피할 것]
- 구현 난이도가 검증되지 않은 기능 나열
- "세계 최초", "유일한" 같은 검증 불가 주장
- 경쟁을 "기존 서비스들"로만 뭉뚱그리기
- **수익 이야기 — Q3-2의 몫입니다**
- 규모가 다른 대기업 사례를 우리 근거로 그대로 가져오기
