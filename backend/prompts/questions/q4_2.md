[문항 의도]
심사 축 — 팀 구성(T). 중심은 "부족하니 도와달라"가 아니라 **"지금 단계에서 무엇을 검증해야 하고, 멘토의 경험을 어디에 쓸 것인가."**
포지셔닝: **실행(만들고 운영하는 것)은 할 수 있으나 검증·시장 진입 경험이 부족하다.** 자기 역량을 깎아내리는 서술은 쓰지 않습니다.

[프로세스 위치]
①~⑧ 중 **지금 막혀 있는 단계**.
어느 단계에서 무엇을 검증해야 하는지로 요청을 특정합니다. 막연히 "전반적인 조언"을 구하지 않습니다.

[골자 사용 규칙]
- 펼쳐 씁니다: **아직 모르는 것** — 단, 그대로 옮기지 않고 **검증·시장 진입 경험 축으로 번역**해서 요청으로 만듭니다.
- 지원자 역량은 ① 문단에서 **강점으로 먼저** 제시합니다 (한 절이 아니라 한 문장).
- 쓰지 않습니다: 문제·해결책·수익·계획을 다시 설명하는 것. 해결책은 ① 의 한 절뿐.

[역량 축 — 분야 중립]
사업에 필요한 역량은 여섯 축입니다: ⓐ 기술·제품 구현 ⓑ 고객·문제 검증 ⓒ 비즈니스 모델·가격·수익화
ⓓ 마케팅·채널·시장 진입 ⓔ 법·제도·규제(개인정보·인허가·위생·안전) ⓕ 운영·공급·파트너(제조·유통·기관 협약).
**입력된 역량이 어느 축에 있는지 판독하고, 요청은 그 반대편 축에서 고릅니다.**
- 개발·공학·기술 → 강점 ⓐ, 요청 ⓑⓒⓓⓔ. ⓐ 안의 요청은 "무엇을 먼저·직접 만들고 무엇은 외부를 쓸지 **범위·우선순위 판단**"까지만
- 경영·회계·마케팅 → 강점 ⓒⓓ, 요청 ⓐ(구조·난이도·도구 적용 가능성) ⓑ ⓔ
- 디자인·콘텐츠 → 강점은 제품 경험, 요청 ⓒⓐⓑ
- 법·행정 → 강점 ⓔ, 요청 ⓐⓓⓒ
- 현장·업계 경험(재배·요식·복지·제조·판매 등) → 강점 ⓑⓕ, 요청 ⓒⓓⓐ(디지털·도구)ⓔ
- 입력이 없으면 → "강점이 확인되지 않았다"고 쓰지 말고 요청 축을 ⓑⓒⓓ 로
**강점 축에 해당하는 영역을 "모른다·부족하다"로 쓰지 않습니다** — 입력과 모순되는 부족은 실격입니다.

[필수 요소]
- 첫 문단 포지셔닝: 현재 단계 한 절 + 입력된 **강점** + "할 수 있는 것 / 경험이 부족한 것"의 경계 한 문장
- 요청 3~4개, 각각 **세 요소**: 지금 단계에서 검증할 것 · 멘토의 경험을 쓸 지점 · 결과가 어디에 반영되는지
- 요청은 강점의 반대편 축에서 (골자 '아직 모르는 것' 과 대응)
- 마무리: 강점은 활용하고 부족한 축은 보완해 "만들 수 있는 것"이 아니라 "고객이 쓰고 지불하는 사업"으로

[권장 요소]
문단 구성 — 이 순서로 **1,200~1,600자**. 같은 말을 되풀이해 채우지 않습니다.

① 포지셔닝 (200~300자)
   제품·서비스 한 절 + **강점을 먼저**(입력된 역량 기반) + "사업으로 발전시키려면 여섯 축이 필요한데 혼자·소규모로 다
   갖추기 어려워 상호보완이 되는 분야에서 도움을 받고자 한다" 한 문장. 약점을 먼저 꺼내지 않습니다. 신분 나열 금지.
②~④ 요청 3~4개 (각 200~300자)
   각각 한 문단. 강점의 반대편 축에서 고릅니다. 요청 하나 = **지금 단계에서 검증할 것 + 멘토 경험을 쓸 지점 + 결과가 반영되는 곳**.
   예를 들어 '고객·문제 검증' 축이라면 — 어떤 고객이 어디서 가장 곤란한지 확인하는 방법, 1차로 만들 범위를 가르는 판단.
   '시장 진입' 축이라면 — 여러 접점 중 어디를 먼저 갈지, 무료 이용자를 반복·유료로 옮기는 방식.
   '법·제도' 축이라면 — 이 분야의 인허가·개인정보·안전 등 지켜야 할 것과 순서.
   강점 축 안의 요청은 "범위·우선순위·직접 하기 vs 외부 활용 판단" 형태로 하나까지만.
⑤ 마무리 (120~200자)
   준비해 갈 것 한 절(계획·가설·시나리오 정리) + "가진 강점은 적극 쓰되 부족한 축을 보완해, 구현 가능한 것에서
   고객이 반복해 쓰고 지불하는 사업으로" 한 문장.

[피할 것]
- **입력된 강점 영역을 "모른다·부족하다"로 쓰기** (기술을 입력한 사람이 "개발 방법을 모른다", 현장 경험자가 "운영을 모른다")
- 역량 목록을 나열하는 문단, 요청을 일반 명사로 끝내기("마케팅 전략 수립", "서비스 개발 방법")
- "전반적인 조언", "네트워크 소개" 같은 막연한 요청
- 첫 문단을 서비스 설명·신분 소개로 채우기 (서비스는 한 절, 신분은 쓰지 않음)
- 혼자인 것을 약점으로만 서술하기, 팀 충원 계획을 억지로 넣기
- **문제·해결책·수익·계획 재설명** (앞 문항이 썼습니다)
- 외부 통계·기사 인용 (이 문항의 몫이 아닙니다)
