# 모두의 창업 신청서 자동 작성기 — 프로젝트 컨텍스트

> 새 세션에서 이 파일만 읽고 작업을 이어갈 수 있도록 정리한 인수인계 문서.
> 작성일: 2026-08-31

---

## 1. 프로젝트 목표

중소벤처기업부 「모두의 창업 프로젝트」(https://www.modoo.or.kr) 도전신청서를 **아이디어 한 문단만 입력하면** 문항별로 자동 작성해 주는 도구.

- 사용자: 창업 아이디어만 있는 일반인 (여러 명이 사용하는 웹 서비스 지향)
- UX 원칙: 사용자는 아이디어 입력 → AI가 만든 초안을 **여러 글 스타일로 읽고 고르기만** → 복사해서 modoo.or.kr에 붙여넣기
- modoo.or.kr은 robots로 자동 접근 차단 → 폼 자동 입력은 불가, **복사·붙여넣기 방식**으로 확정

## 2. 결정된 사항

| 항목 | 결정 |
|---|---|
| 현재 단계 | 데모/MVP |
| 데모용 모델 | Claude Sonnet (claude-sonnet-4-6). **개발 중 무료 테스트는 OpenRouter `minimax/minimax-m3:free`** (2026-08-31 확정, 아래 진행 상황 참고) |
| 최종 기본 모델 | 로컬 Llama 70B (Ollama → 트래픽 늘면 vLLM) |
| 모델 연결 방식 | **OpenAI 호환 API 하나로 통일**. `base_url / api_key / model` 세 값만 설정 파일로 분리. Claude·Gemini는 LiteLLM 프록시로 같은 형식 사용 |
| 프롬프트 관리 | 코드에 하드코딩하지 않고 **md 파일**로 분리 (아래 4절) |
| RAG | 로컬 문서(PDF/PPTX/DOCX) 먼저, 웹 검색(뉴스·근거자료)은 2차 |
| RAG 프레임워크 | MVP는 직접 구현(200줄 내외). 필요해지면 LlamaIndex 검토 (LangChain보다 문서 검색 특화) |
| 백엔드 | Python + FastAPI |
| 프론트엔드 | 기존 React 아티팩트를 `frontend/src/App.jsx`로 이관(Vite + React 19 + Tailwind v4). API 호출은 `frontend/src/api.js` → 백엔드 |

### 모델 관련 주의
- Llama 70B Q4 양자화 기준 VRAM 40GB 이상 필요 (24GB×2, 48GB×1, Mac 통합메모리 64GB+). 미만이면 CPU 오프로드로 문항당 수 분 소요.
- Llama 3.x 계열은 한국어 장문에서 번역투·반복·존댓말 흐트러짐 발생 가능. **같은 입력으로 Sonnet vs Llama 70B vs 한국어 강한 모델(Gemma 3 27B, EXAONE 3.5 32B 등) 나란히 비교**한 뒤 기본 모델 최종 결정.
- 아티팩트 환경의 Anthropic API는 `max_tokens: 1000` 제한 → 한국어 2000자 문항을 한 번에 못 채움. 그래서 초안은 1000~1300자로 생성하고 "이어쓰기"로 보충하는 구조. 자체 백엔드에서는 이 제한이 없으므로 한 번에 1500~1900자 목표로 바꿔도 됨.

## 3. 신청서 구조 (modoo.or.kr 도전하기 화면)

전체 4단계: `01 분야 선택 → 02 아이디어 작성 → 03 멘토 기관 선택 → 04 확인·제출`
핵심은 02. 이미지는 **전체 문항 합산 최대 10장**.

### 01. 분야(트랙) 선택
- **일반/기술 분야**: 창의적 아이디어·기술 융합으로 불편 해소, 새 가치 창출
- **로컬 분야**: 지역자원 기반 창의성·혁신 결합. 예비창업자 또는 업력 7년 이내 기창업자(이종창업) 대상. 예비창업자 판단은 공고일('26.8.20) 기준 사업자등록 유무.

### 02. 아이디어 작성 (두 트랙 공통, Q6 선택지만 다름)
| 문항 | 내용 | 제한 | 필수 | 이미지 |
|---|---|---|---|---|
| Q1 | 아이디어 한줄 소개 | 100자 | 필수 | - |
| Q2 | 아이디어를 떠올린 배경 이야기 | 2000자 | 필수 | 가능 |
| Q3-1 | 기존 제품·서비스 대비 차별점, 해결 문제 | 2000자 | 필수 | 가능 |
| Q3-2 | 수익 창출 계획 | 2000자 | 필수 | 가능 |
| Q4-1 | 사업화 계획 | 2000자 | 필수 | 가능 |
| Q4-2 | 책임멘토에게 받고 싶은 도움 | 2000자 | 필수 | 가능 |
| Q5 | 소개 영상 링크 | - | 선택 | - |
| Q6 | 사업 분야 선택 | - | 필수 | - |
| Q7 | 현재 창업 여부 (사업자 아님 / 사업자) | - | 필수 | - |
| Q7-1 | (사업자만) 기존 사업 아이템과 이번 아이디어의 차이 | 2000자 | 조건부 필수 | - |
| Q8 | 사업화할 수 있는 본인 역량 | 2000자 | 필수 | - |
| Q9 | 팀원 수 (본인 제외, 팀원없음~10명이상) | - | 선택 | - |
| Q10 | 대중 공개용 아이디어 자랑 (홈페이지 공개, 좋아요) | 100자 | 선택 | - |
| Q11 | 서약서 동의 3개 | - | 필수 | - |

**Q6 선택지**
- 일반/기술: IT, 교육, 금융, 운영관리, 네트워킹, 농축/수산업, 라이프스타일, 마케팅/PR, 모빌리티, 미디어/엔터테인먼트, 바이오/의료, 에너지/자원, 유통/물류, 임팩트, 재무, 프롭테크, 하드웨어, 기타
- 로컬: 패션, F&B, 뷰티, 생활

### 03. 멘토 기관
육성 프로그램 지역 선택. 현재 타깃 예시: `충남 > 백석대학교 산학협력단`

### 자동 생성 대상 vs 사용자 직접 입력
- 자동 생성: Q1, Q2, Q3-1, Q3-2, Q4-1, Q4-2, Q7-1(조건부), Q8, Q10 + Q6 추천
- 직접 입력: Q5, Q7 여부, Q9, Q11, 멘토 기관, 이미지

## 4. 프롬프트 md 파일 구조 (설계안)

```
prompts/
  system.md            # 페르소나(신청서 대필 전문 작가), 공통 규칙
  tracks/
    tech.md            # 일반/기술 강조점
    local.md           # 로컬: 지역자원·지역성 연결 강조
  questions/
    q1.md  q2.md  q3_1.md  q3_2.md  q4_1.md  q4_2.md  q7_1.md  q8.md  q10.md
  styles/
    story.md           # 스토리텔링형: 경험·장면으로 시작, 공감 유도
    logic.md           # 논리·근거형: 문제→원인→해결→근거
    plain.md           # 간결·실무형: 짧은 문장, 핵심만
```

**조립 순서**: `system + track + question + style + 참고자료(RAG) + 지원자 입력(아이디어·창업여부·역량·팀원)`

**공통 규칙 (system.md에 들어갈 것)**
- 1인칭('저/저희'), 심사위원이 읽는 글
- 허위·과장·근거 없는 수치 금지, 입력에 없는 사실 지어내지 않기
- 제목/소제목/마크다운 기호/이모지 금지, 문단은 줄바꿈으로만
- 답변 본문만 출력
- 글자 제한 절대 초과 금지

**questions/q*.md 형식**: `문항 의도 / 필수 요소 / 권장 요소 / 피할 것 / 분량 / 좋은 예·나쁜 예`
→ "필수 요소"는 구조화(리스트)해서 생성 후 검증에도 재사용.

## 5. 문항별 필수·권장 내용 분석 (스타일·분량과 무관한 핵심)

### Q1. 한줄 소개 (100자)
- 필수: 대상 고객 / 해결 문제(또는 제공 가치) / 제품·서비스 형태 — 세 가지가 한 문장에
- 권장: 기존 방식과 구별되는 핵심 한 단어("예약형", "구독형", "동네 기반" 등)
- 피할 것: "혁신적인", "AI 기반" 같은 수식어만 있고 실체 없는 문장

### Q2. 배경 이야기 (2000자)
- 필수: 문제를 겪거나 목격한 구체적 상황(누가·언제·어디서) / 왜 방치되고 있는지 / 문제→아이디어로 넘어간 계기
- 권장: 문제 크기 근거(직접 물어본 사람 수, 관찰 횟수, 공개 통계 1~2개) / 지원자와 문제의 개인적 연결(왜 하필 내가) / 로컬 트랙이면 지역 자원·특성 연결
- 피할 것: 시장 규모 인용만으로 채운 배경, 문제 없이 아이디어부터 등장

### Q3-1. 차별점·해결 문제 (2000자)
- 필수: 해결 문제 한 문장 정의 / 현재 대안(경쟁 제품뿐 아니라 "그냥 참는다", "엑셀로 한다" 같은 우회책 포함) / 대안이 부족한 이유 / 우리 아이디어가 그 부족함을 메우는 방식
- 권장: 2~3개 기준(가격·접근성·시간·품질)으로 대안 비교 / 쉽게 복제되지 않는 이유(관계·데이터·지역 밀착·노하우) / 해결 시 고객에게 생기는 변화
- 피할 것: "기존 서비스는 불편하다"로 끝나는 추상 비교, 경쟁자 없다는 주장

### Q3-2. 수익 창출 (2000자)
- 필수: 돈 내는 주체(고객≠결제자면 구분) / 무엇에 어떤 방식으로 받는지(건당·구독·수수료·광고·B2B) / 대략 가격 수준과 근거
- 권장: 초기 모델 vs 확장 모델 구분 / 단위 경제성(한 건당 남는 돈, 원가 구조) / 첫 1년 보수적 매출 가정 / 수익 모델이 고객 행동과 충돌하지 않는 이유
- 피할 것: 근거 없는 억 단위 전망, 수익원 5개 이상 나열

### Q4-1. 사업화 계획 (2000자)
- 필수: 단계별 계획(검증→시제품/MVP→첫 고객→확장) / 각 단계에서 확인할 것 / 6개월~1년 내 실행 가능한 첫 단계의 구체 행동
- 권장: 단계별 시점 / 필요 자원(자금·인력·장비)과 조달 / 프로그램의 창업활동자금·멘토링을 어느 단계에 쓸지 / 초기 고객 확보 채널 / 리스크와 대응(인허가·원자재·파트너 이탈)
- 피할 것: "앱 개발 후 마케팅으로 확장" 수준의 뭉뚱그림

### Q4-2. 책임멘토 도움 (2000자)
- 필수: 부족하다고 인정하는 영역 / 그 영역에서 원하는 구체적 조언 / 멘토링을 사업 계획 어느 단계에 어떻게 적용할지
- 권장: 멘토 조언으로 판단이 달라질 의사결정 지점 2~3개(가격 정책, 첫 매장 입지, 제조 위탁 여부 등) / 멘토링 기간 목표 / 스스로 시도해본 것과 한계
- 피할 것: "전반적인 조언", "네트워크 소개" 같은 막연한 요청만

### Q7-1. 기존 사업과의 차이 (사업자만, 2000자)
- 필수: 기존 사업의 업종·고객·수익구조 / 새 아이디어와의 차이(이종창업 요건 — 업종 차이 분명해야) / 기존 경험이 새 아이디어에 주는 이점
- 권장: 시간·자원 배분 계획 / 시너지 또는 명확한 분리
- 피할 것: 기존 사업의 확장·리뉴얼로 읽히는 설명

### Q8. 본인 역량 (2000자)
- 필수: 아이디어와 직접 연결되는 경험·기술·관계(각 항목을 아이디어의 어느 부분에 쓰는지 연결) / 부족한 역량과 보완 방법(팀원·외주·멘토·학습)
- 권장: 이미 실행해본 것(사전 조사, 시제품, 예비 고객 반응) — 가장 강력한 근거 / 팀원 역할 분담 / 끝까지 밀어붙일 동기
- 피할 것: 무관한 학력·자격증 나열, 없는 경력 과장

### Q10. 대중 공개용 자랑 (100자)
- 필수: 일반인이 3초 안에 이해 / Q1보다 감정적·친근한 톤
- 권장: 공감 포인트·궁금증 유발(질문형, 상황 제시형)
- 피할 것: Q1 복사, 전문용어

### 문항 전체 관통 원칙
- Q2 문제 → Q3-1 차별점 → Q3-2 수익 → Q4-1 계획 → Q8 역량이 **한 줄로 연결**돼야 함. 심사는 "이 사람이 실제로 하겠다"는 일관된 인상으로 갈림.
- 숫자는 적게, 출처나 확인 방법 있는 것만.
- 이미지 10장 배분 권장: Q2(문제 상황 사진), Q3-1(비교표), Q3-2(수익 구조도), Q4-1(로드맵).

## 6. 생성 파이프라인 (설계안)

1. **입력 수집**: 아이디어, 트랙, 창업 여부(+기존 사업), 역량, 팀원 수, 원하는 스타일(복수)
2. **아이디어 구조화** (사전 호출 1회): 문제/고객/해결책/수익 가설로 정리 → 모든 문항에 공통 주입해 일관성 확보
3. **참고자료 검색** (RAG, 문항별): 문항 의도 + 아이디어로 검색, 상위 3~5 청크
4. **문항 × 스타일 생성** (병렬, 로컬 모델은 동시 2~3개 제한)
5. **후처리**: 글자 수 초과 시 문장 단위 절단, 마크다운 제거
6. **검증 호출**: q*.md의 필수 요소 체크리스트를 주고 JSON으로 포함 여부 판정 → UI에 "누락: 수익 주체" 표시 → 누락 항목만 보완 생성
7. **Q6 분야 추천**: 트랙별 선택지 목록에서 하나 고르고 이유 (JSON)
8. **이어쓰기**: 기존 글 + "반복 없이 새 근거·사례·계획만 N자 이내로 이어서" 요청, 결과를 append

## 7. RAG 설계안

**로컬 문서 (1차)**
- 파싱: PDF → pymupdf, PPTX → python-pptx, DOCX → python-docx
- 청크: 500~800자
- 임베딩: bge-m3 (한국어 다국어 무난)
- 저장소: Chroma 또는 LanceDB
- `/ingest` 엔드포인트로 업로드 → 인덱싱

**웹 검색 (2차)**
- 검색 API: Tavily / Brave Search / SerpAPI 중 택1
- 본문 추출: trafilatura
- 모델로 "이 아이디어와 관련된 사실만 출처·날짜와 함께 요약" → 프롬프트 주입
