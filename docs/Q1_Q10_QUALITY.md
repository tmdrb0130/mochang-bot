## 2. 원인 (지금 프롬프트)

| 문항 | 원인 |
|---|---|
| Q1 | 작업 15 가 **정의형(명사 맺음)을 금지**하고 고객·결과 중심 짜임 4종으로 돌림 → 구체 기능이 빠지고 "자신감·효율화" 같은 추상어만 남음. 사용자가 싫어한 건 정의형이 아니라 "저는 …에게 …를 제공하는 앱입니다" **빈 틀**. 85자 압축(작업 21)도 기능부터 깎음 |

## 3. 규칙 (두 문항 공통)

1. **구체 기능(하는 일) 2~3개 필수** — 아이디어 설명에 있는 기능어를 그대로 살린다("생성·분석·알림·수거·배송·매칭·저장·추천"). 추상 가치어로 대신하지 않는다.
2. **추상 가치어 금지 목록**: 자신감·효율화·불편 해소·만족·편리·도움이 되다·가치를 제공·혁신·스마트. 쓰려면 기능으로 바꿔 쓴다.
3. 고객은 짧게(한 절) 또는 생략 가능. 고객 서술이 기능을 밀어내면 안 된다.
4. 길이: Q1 70~95자, Q10 60~95자. 한도 100. 초과 시 작업 21 압축 재생성 — **압축할 때 기능을 먼저 깎지 않고 수식어·고객 절을 깎는다**(`shorten.md` 에 명시).
5. 짜임은 문항당 **2종만**, 회전 유지:
   - Q1: (a) **기능 나열 정의형** "[입력/재료]를 바탕으로 A 하고, B 를 분석해 C 를 제공하는 [형태]" (명사 맺음 허용) (b) **문제→기능형** "[문제 한 절]에, A 하고 B 해 주는 [형태]"
   - Q10: (a) **홍보형** "[고객의 상황/문제 호소 한 절]. A 부터 B 와 C 까지 [주체]가 함께합니다/해 드립니다." (b) **소개형** "[입력/재료]하면 A 하고, B 까지 C 해 주는 [형태]"
6. **질문형 맺음 금지**(Q10 포함). "~지 않을까요", "~해 보세요" 로 끝나지 않는다. 홍보형의 호소는 첫 절에서 명령형·부정 명령형("혼자 준비하지 마세요")으로.
7. Q1 과 Q10 이 같은 문장이면 안 된다(코드: 4-gram Jaccard≥0.6 이면 Q10 재생성).
8. 예시 소재는 `q1_structures.md`·`q10.md` 에서 **제조·농업·오프라인 소재를 섞어** 두 분야 이상(일반화 4절).
