# 작업 32 — Q8(아이디어를 사업화할 수 있는 본인의 역량) 품질: 입력된 자산만 사업화 역량으로 번역

> Q8 의 중심 질문: **"왜 이 사람이 이 사업을 실행할 수 있는가."** 특정 인물상(대학생·20대·컴공·남성) 전제 금지 — **입력된 강점·경험·자원만** 가지고 쓴다.

## 1. 골든 예문 (사용자, 컴공 전공 입력 기준 — 다른 입력이면 문장 구조가 달라져야 한다)

> 저는 컴퓨터공학을 전공하며 쌓은 소프트웨어 개발 지식과 프로젝트 경험을 바탕으로 본 아이디어를 실제 서비스로 구현할 수 있는 역량을 갖추고 있습니다.
>
> 전공 과정과 프로젝트를 통해 프로그래밍, 데이터 처리, 웹 서비스 개발 등 서비스 구현에 필요한 기술을 경험해 왔습니다. 이러한 역량은 이력서와 지원 직무를 분석하여 예상 질문을 생성하고, 사용자의 답변을 수집·분석하는 AI 면접 코칭 서비스의 초기 MVP를 직접 구현하고 검증하는 데 활용할 수 있습니다.
>
> 저의 강점은 단순히 기술을 알고 있는 것에 그치지 않고, 아이디어를 실제 작동하는 형태로 구현하고 문제가 발생했을 때 원인을 분석하여 개선할 수 있다는 점입니다. 초기에는 핵심 기능을 직접 개발하여 빠르게 서비스를 구현하고, 실제 사용자 테스트를 통해 기능의 필요성과 개선점을 확인하며 서비스를 발전시킬 계획입니다.
>
> 반면 기술 개발에 비해 비즈니스 모델 설계, 마케팅, 가격 정책, 고객 확보, 개인정보 및 AI 활용과 관련된 법적·제도적 검토 등은 상대적으로 경험이 부족한 영역입니다. 이러한 부분은 책임멘토의 조언과 외부 전문가와의 협업, 고객 인터뷰 및 시장 검증을 통해 보완하고자 합니다.
>
> 제가 보유한 기술적 실행력을 중심으로 초기 서비스를 직접 구현하고, 부족한 역량은 외부의 전문성과 사용자 피드백을 활용해 보완함으로써 아이디어를 실제 고객이 사용할 수 있는 사업으로 발전시키고자 합니다.

## 2. 생성 원칙 (사용자 — `q8.md` 맨 위 [원칙] 절로 그대로 옮긴다, 분야 중립 문장)

1. **나이·성별·학력·직업·신분을 근거 없이 역량으로 평가하지 않는다.** 지원자가 직접 입력한 전공·직무 경험·프로젝트·자격·기술·업계 경험·문제를 겪은 경험·네트워크·활동 경험만 쓴다.
2. 입력된 강점 중 **이 아이디어와 직접 연결되는 요소를 먼저** 고르고, **보유 역량 → 그것을 보여주는 경험 → 이 사업에서의 활용 방법** 순서로 쓴다.
3. 강점 유형에 따라 앞세우는 것이 달라진다(Q4_2_QUALITY 1-1 의 역량 축 6개와 같은 표): 개발·기술 경험 → 구현·MVP 제작 / 영업·마케팅 경험 → 고객 발굴·시장 검증 / 경영·회계 경험 → BM·운영 / 특정 산업 경험 → 현장 이해·네트워크 / 디자인·콘텐츠 → 제품 경험 / **관련 경력이 없으면** → 문제를 직접 겪은 정도·학습 경험·실행 가능한 자원. **존재하지 않는 역량·경험·자격·결과물을 만들지 않는다.**
4. 부족한 역량은 부정적으로 강조하지 않고 멘토링·협업·외부 전문가·교육으로 **보완할 영역**으로 짧게 제시한다(상세는 Q4-2 몫 — Q4-2 와 같은 축을 반복 설명하지 않는다).
5. 사업화 일정·매출·타깃 고객 설명·시장 기사 등 **다른 문항의 내용을 반복하지 않는다.**

## 4. 새 문단 구조 (`q8.md` 교체) — 총 1,200~1,600자. **입력에 따라 문단 순서가 바뀐다**

| 순서 | 내용 | 분량 | 규칙 |
|---|---|---|---|
| ① 한 문장 주장 | "[입력된 핵심 역량/경험]을 바탕으로 이 아이디어를 실행할 수 있다" | 80~150 | 신분 나열 금지("대학생으로서" ×) |
| ② 강점 → 경험 → 활용 | 가장 연결이 강한 강점 1~2개: 무엇을 해봤고(기간·규모는 입력에 있을 때만) → 이 사업의 어느 부분(구현/고객 이해/판로/운영/전문성/네트워크)에 어떻게 쓰는지 | 350~500 | 존재하지 않는 경험 금지 |
| ③ 문제와의 연결 | 지원자가 그 문제를 **직접 겪었거나 가까이서 본 경험**(인테이크 evidence/idea 에 있을 때만) → "제안에 그치지 않고 어디가 불편한지 안다" | 150~300 | 없으면 문단 생략 |
| ④ 실행 방식 | 강점으로 **직접 실행 가능한 부분부터 빠르게 검증**한다는 한 문단(개발자=직접 구현, 영업직=직접 고객 인터뷰·판매, 현장 경험자=시범 운영) | 150~250 | Q4-1 일정 재서술 금지 |
| ⑤ 보완 영역 | 강점의 반대편 축(Q4_2 1-1 표) 2~3개를 "보완할 영역"으로 짧게 + 방법(멘토·협업·교육) | 150~250 | 부정 강조 금지, Q4-2 상세 반복 금지 |
| ⑥ 마무리 | "강점을 핵심으로 쓰고 부족한 것은 보완해 고객이 쓰는 제품·서비스로" 한 문장 | 60~120 | |

입력이 빈약할 때(capability 없음·evidence 없음): ①②는 **문제를 겪은 경험·학습 계획·쓸 수 있는 자원**으로, 억지 경력 금지. 인테이크 capability 카드가 먼저 받게(작업 24).
