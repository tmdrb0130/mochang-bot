## 원인과 변경

- 신뢰도 정렬 후 앞 6장만 고르면 뉴스가 다른 검색 주제·논문·공식 통계보다 먼저 자리를 차지한다. 관련 검색 후보 안에서 검색 주제·자료 종류·도메인을 고르게 선택하도록 변경했다.
- 검색어에 실태 연구·논문과 실제 경쟁 서비스·이용 요금 관점을 포함하도록 프롬프트와 실패 시 기본 검색어를 개선했다. 학술 API가 주제와 관련된 검색어로 호출될 기회를 만든다. 논문 결과가 반드시 나온다는 보장은 없다.
- 벡터 저장소의 문서 수가 충분해도 한 출처·한 종류라면 웹 검색을 보완한다. 재사용 경로도 이미 조사한 URL 제외와 도메인 제한을 지킨다.
- 한 기사의 서로 다른 사실을 다른 문항에 나누던 배분을 출처 단위로 묶었다. 추적 파라미터·fragment로 같은 자료가 다른 출처로 세어지는 것도 방지한다. 문항 내에서는 새로운 출처부터 배분한다.
- 공통 자료의 배정을 보완 검색 전에 고정하고 새 근거를 해당 문항에 배정한다. 보완 검색 결과와 합칠 때 출처별로 번갈아 넣고 해당 문항의 공통 근거를 우선 보존한다.
- 보완 검색 모델에는 해당 문항에 배정된 근거만 보여 준다. 관련 출처가 한 곳뿐이면 다른 종류의 자료를 더 찾도록 지시한다. 모델이 빈 배열·잘못된 JSON을 반환해도 출처가 2곳 미만이면 상한 내에서 보완 검색 1건을 수행한다.
- 사실 캐시 키를 `research-facts-v2-diverse`로 변경했다. 운영 캐시는 삭제하지 않아 롤백 시 기존 캐시를 사용할 수 있다.

## 나중에 빠르게 적용

학생들이 사용하지 않는 시간에 **관리자 PowerShell**에서 아래 명령을 실행한다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:\Users\bon505\Desktop\mochang-research-diversity\scripts\apply_research_diversity.ps1" -Apply
```

`-Apply` 없이 실행하면 Git 상태와 변경 목록만 확인한다. 실제 적용은 기존 `deploy_window.py`로 두 큐가 비고 최근 활동이 없는지 확인한 뒤, `nssm stop mochang-api` → `git merge --ff-only` → `nssm start mochang-api` → `/health` 확인 순서다. 프론트 빌드·의존성 설치·DB 변경은 없다. 서비스가 멈춘 짧은 시간에는 접속이 실패할 수 있으므로 사용 종료 시간에 실행해야 한다. 큐가 비어 있다는 것이 접속 학생이 없음을 보장하지 않는다.

운영에 다른 변경이 생겨 fast-forward가 불가능하면 파일이나 서비스를 바꾸기 전에 중단한다. 그때는 개발 worktree에 최신 운영 변경을 통합하고 테스트한 뒤 적용한다. 스크립트는 현재 실행하지 않았다.
