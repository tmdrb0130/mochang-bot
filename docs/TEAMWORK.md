# 병렬 세션 작업 규칙 (TEAMWORK)

## 0. 최상위 규칙 — 작업 범위는 이 폴더뿐

**쓰기가 허용되는 곳은 `C:\Users\bon505\Desktop\mochang-bot` 안뿐이다.**
이 PC 에는 다른 대형 프로젝트(bustartup.kr)의 **라이브 서비스**가 돌고 있고,
모창봇은 그 프로젝트의 nginx 에 50001 포트로 얹혀서 공개되고 있다.

- nginx 설정(50001 블록 포함), `vsp-*` NSSM 서비스 5종, 다른 프로젝트 폴더 —
  **전부 그쪽 라이브 서비스 소속. 수정·재시작·중지 절대 금지.**
- 리포 밖을 건드려야만 풀리는 문제(nginx 프록시, 서비스 등록 등)는
  직접 하지 말고 `WORKBOARD.md` "조율 필요"에 적고 사용자 결정을 기다린다.

> 세션 3개가 **같은 폴더, 같은 브랜치**에서 동시에 작업한다.
> 모든 세션은 작업 시작 전에 이 파일과 `docs/WORKBOARD.md` 를 읽는다.
> 이 파일은 **규칙(거의 안 바뀜)**, `WORKBOARD.md` 는 **상태판(수시로 바뀜)**.

## 2. 파일 소유권 — 자기 구역 밖은 절대 수정 금지

| 경로 | 소유 | 비고 |
|---|---|---|
| `frontend/**` | 세션2 | `dist/` 재빌드 포함 |
| `backend/**`, `tests/**` | 세션3 | 프롬프트 md 포함 |
| `docs/**`, `PROGRESS.md`, `README.md`, `CLAUDE.md` | 세션1 | 예외: `WORKBOARD.md` 의 자기 세션 로그 절은 각자 씀 |
| `backend/config.yaml` | 세션3 | 단, **모델 전환은 사용자 결정 후에만** |
| `scripts/**` | 세션3 | |

- 다른 구역의 파일은 **읽기는 자유, 쓰기는 금지**. 경계를 넘어야 하는 작업이 생기면
  `WORKBOARD.md` "조율 필요"에 적고 세션1(사용자)을 거친다.
- 인터페이스 파일(백엔드 API 응답 스키마 등)을 바꾸면 반드시 `WORKBOARD.md` 에 먼저 공지.
  현재 세션2가 의존하는 백엔드 API: `POST /jobs/{kind}`, `GET /jobs/{job_id}`, `GET /jobs` —
  **세션3은 이 세 엔드포인트의 응답 형태를 바꾸지 않는다** (필드 추가는 허용, 삭제·개명 금지).

## 3. git 규칙

- **브랜치 전환·rebase·amend·`git checkout --`·`git add .`/`git add -A` 전부 금지.**
  같은 워킹트리를 셋이 쓰므로 브랜치를 바꾸면 남의 파일이 통째로 뒤집힌다.
- 커밋할 때는 **자기 소유 경로만 명시적으로** `git add <경로>` 한다.
  예: 세션2 → `git add frontend/`, 세션3 → `git add backend/ tests/`.
- 커밋 메시지는 `[세션N]` 접두어를 붙인다. 예: `[세션2] V1: 프론트를 작업 큐 API 로 전환`.
- push 는 세션1이 하거나, 하기 전에 `WORKBOARD.md` 에 적는다 (동시 push 방지).
- 커밋 전 `pytest` 통과는 **세션3만** 필수 (프론트는 `npx vite build` 통과).
- 커밋에 Co-Authored-By / Claude 관련 트레일러를 넣지 않는다.

## 4. 실행 환경 충돌 방지 — 포트·프로세스·서비스

이 PC 는 **공개 서비스 운영 중**이다 (`bustartup.kr:50001`, NSSM 서비스 `mochang-api` 가 :8000 점유).

| 자원 | 규칙 |
|---|---|
| 포트 8000 | `mochang-api` 서비스가 쓰는 중. **개발용 uvicorn 이 필요하면 :8001 등 다른 포트로** 띄운다. `nssm stop mochang-api` 는 공개 서비스 중단 → **사용자 승인 필수** |
| 포트 5173 | 세션2 전용 (`npm run dev`) |
| NSSM 서비스 6종 (`vsp-*`, `mochang-api`) | 어떤 세션도 임의로 stop/restart 금지. 필요하면 WORKBOARD "조율 필요"에 적기 |
| SSH 터널(30800)·Ollama | 로그인 세션 프로세스 — 죽이면 생성이 전부 실패. 건드리지 않기 |
| `backend/.usage.json`, `backend/.cache/` | 로컬 런타임 파일. 커밋·삭제 금지 |
| 실모델 호출 | 라마는 한도 없음. OpenRouter(minimax) 호출은 하루 50회 한도 — 실호출 검증은 WORKBOARD 에 횟수 기록 |

## 5. 작업 흐름 (모든 세션 공통)

1. 시작: `TEAMWORK.md`(이 파일) + `WORKBOARD.md` 읽기 → 자기 배정 확인.
2. 착수: `WORKBOARD.md` 자기 로그 절에 "시작: 작업명, 건드릴 파일" 한 줄 추가.
3. 작업: 소유권 지키며 진행. 경계 밖 문제 발견 → 고치지 말고 "조율 필요"에 기록.
4. 완료: 검증(빌드/테스트) → 자기 경로만 add·커밋 → `WORKBOARD.md` 로그에 "완료 + 커밋 해시".
5. 세션1이 주기적으로 WORKBOARD 를 정리하고 PROGRESS.md 로 옮긴다. **PROGRESS.md 직접 수정 금지.**

## 6. 막히면

- 사용자 결정이 필요한 것(모델 선택, 서비스 재시작, API 변경 등) → `WORKBOARD.md` "조율 필요"에
  적고 **그 작업만 멈추고 다른 배정 작업으로 넘어간다**. 세션 전체를 멈추지 않는다.
- 남의 구역 파일이 이상해 보여도 직접 고치지 않는다 — 그 세션이 작업 중일 수 있다.
