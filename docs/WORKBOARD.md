### 작업 10 상세 — GPU 한계 측정과 워커 상향 (세션3 + 사용자)

**현황 근거** (어제 측정, PROGRESS·BOTTLENECKS):
- 백엔드 큐 `max_workers: 12` (본문) + 4 (조사) — 부하테스트 내내 `running=12` 고정, 대기 최대 90건.
  **대기(2분49초)가 실행(24초)의 7배 — 병목은 GPU 가 아니라 우리 쪽 워커 수.**
- vLLM 직접 45 동시 호출은 45/45 성공, 73초 — GPU 쪽에 여유가 있다는 뜻.

**측정 (코드 수정 없음, 세션3):**
1. vLLM `/metrics` 를 터널(30800) 경유로 조회 — `vllm:num_requests_running`,
   `vllm:num_requests_waiting`, `vllm:gpu_cache_usage_perc`(KV 캐시 사용률)가 핵심.
   SSH 필요 없음 — 백엔드가 쓰는 같은 포트다.
2. `scripts/load_test.py` 로 동시성을 **단계적으로** 12 → 20 → 30 → 45 올리며
   문항당 p50/p95 실행 시간과 `gpu_cache_usage_perc` 를 기록.
   **KV 캐시가 90% 근처로 가거나 p95 가 꺾이는 지점의 한 단계 아래가 안전 상한.**
3. `nvidia-smi` (GPU 사용률·메모리)는 사용자가 PuTTY 로 원격 서버에서 확인해 값만 전달.

**적용:** `backend/config.yaml` `max_workers` 를 측정된 안전 상한으로 (한 줄).
되돌리기도 한 줄이라 위험 낮음. 조사 워커(4)도 같은 방식으로.

**⚠️ 조율:** 부하 테스트는 공유 GPU 서버에 실부하를 건다 — **실행 시점은 사용자 승인 후**
(한가한 시간대 권장). GPU 서버 자체 설정(vLLM 재기동, `--max-num-seqs` 등)은 이 리포 밖 —
필요해지면 사용자가 직접.
