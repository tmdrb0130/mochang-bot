  4-1. 요청 한 바퀴 (학생 한 명)
     1) POST /jobs/intake  → 조사 큐: 아이디어 공통 조사(검색어 4개 → 검색 → 페이지 6장 → 사실 추출) → 인테이크(슬롯 9개 판정 + 카드)
        프론트는 GET /jobs/{id} 를 2.5초마다 폴링. 카드는 만들어지는 대로 보인다.
     2) 학생이 카드에 답하는 동안 프론트가 문항 8개의 조사를 뒤에서 미리 시작 (동시 3).
     3) [초안 만들기] → 문항마다 POST /jobs/research(공통 조사 상속 + 보완 검색 0~2개) → POST /jobs/generate
        생성 = 사업계획 골자(아이디어당 1회, 캐시) + 문항 프롬프트(system·track·question·style·사실·참고자료) → Qwen →
        후처리(refine: 지어낸 수치·상용구 제거) → polish(모델 1회 고쳐쓰기) → 길이 보정(shorten/lengthen/auto-extend)
     4) 끝날 때마다 storage 가 drafts / generations / research 테이블에 남긴다 (서비스 DB + 전체기록 DB).
     5) 외국어 화면이면 POST /jobs/translate 로 읽기 번역 (조사 큐, priority 50).
     학생 1명 ≈ 모델 호출 30~50회. GPU 포화점(동시 40~60 요청/장)에 맞춰 워커·우선순위가 잡혀 있다.

  4-2. 왜 이렇게 생겼나 (핵심 결정)
     * 모델 연결은 OpenAI 호환 API 하나로 통일 — config.yaml 의 base_url/api_key/model 세 값만 바꾸면 OpenRouter·Ollama·vLLM 어디든 붙는다.
     * 프롬프트는 코드에 없다. 전부 backend\prompts\*.md (34개). 바꾸면 재시작만 하면 된다.
     * OpenRouter 무료 모델(하루 50회)로 시작 → 2026-09-01 자체 GPU 서버 라마 70B → 09-02 Qwen3.8-27B-FP8 로 교체
       (A/B: 문항당 32초/1,609자 vs 라마 61초/1,153자) → 09-03 복제본 2개.
     * 모든 긴 작업은 큐(/jobs) — 강의실 40명이 동시에 눌러도 429 폭주 대신 "대기 순번" 을 보여준다.
     * vLLM 우선순위 스케줄링: 조사·카드(0) < 번역(50) < 본문(100) < 마무리(200). GPU 가 붐빌 때 카드가 먼저 나온다.
     * 저장은 고지 없이 한다(2026-09-02 사용자 결정). 계정 로그인은 도입하지 않았다. 초안 열쇠·공유 토큰·브라우저 익명 id 로 대신한다.

  * 생성문의 수치·사례는 모델이 참고자료 안에서만 쓰도록 강제하지만(refine 이 목록 밖 수치를 지움) 최종 사실 확인은 학생 몫이다. 화면에 그렇게 안내한다.

  카드/슬롯    인테이크가 묻는 항목(고객·문제·대안·수익 등 9슬롯). 카드 1장 = 슬롯 1개의 보기들
  조사(research) 문항에 넣을 출처 있는 사실을 웹·공공 API 에서 모으는 단계. 공통 조사(아이디어당 1회) + 보완 검색(문항당 0~2개)
  골자(outline) 아이디어당 1회 만드는 사업계획 뼈대. 문항 9개가 공유해 서로 다른 말을 하지 않게
  refine / polish  후처리. refine = 코드 규칙(모델 호출 0), polish = 모델 1회 고쳐쓰기
  finisher     마무리 작업자. 나간 학생의 빈 문항을 낮은 우선순위로 채움
  draft_id / draft_key / share  초안 묶음 id / 그 초안의 접근 열쇠 / 다른 기기용 공유 토큰
  서비스 DB / 전체기록 DB / 스냅샷   §8
  NSSM         Windows 에서 아무 프로그램이나 서비스로 돌려 주는 도구. 죽으면 되살린다
  NodePort     k8s 가 노드의 포트(30000~32767)로 서비스를 여는 방식. 30801 = vLLM
  vLLM         LLM 서빙 서버. OpenAI 호환 API 를 낸다. priority 스케줄링 사용
  Evicted      k8s 가 디스크·메모리 압력으로 쫓아낸 파드. 껍데기만 남아 있음
